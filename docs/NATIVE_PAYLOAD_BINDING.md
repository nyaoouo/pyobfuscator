# Ordinary payload contribution binding

The Windows demo defaults to `PYOBF_NATIVE_DEMO_PAYLOAD_BINDING=strict`. Its critical math
is in the private selected `pyobf_demo_bound_compute`, receiving the current handoff lease.
The compiler binds every retained original normal edge and explicit point701 to the existing
owned-context contribution protocol. The real outer serves derived words from the frozen
post-authentication path fold. A successful lifecycle Boolean alone cannot supply these words.

`decoupled` explicitly retains the earlier, weaker math export. It is required for manual
single-function profiles without SDK markers or the contribution provider. Strict selection
requires both. This option controls the sample consumer; it is not a general authorization
policy or a new public SDK.

## Two-phase build dependency

```text
independent early material + generated events header
    -> private fold reference + required recipe overlay
    -> payload/SDK source -> requests -> optional O2/archive -> CFF -> final inner DLL/report
    -> late exact-child plan -> authenticated package
    -> outer code -> raw parent -> reserved data fill -> final parent/report
```

`tools/release_material.py` owns the bounded early schema, event generation, header and fold.
Its document contains only version, seed and events. It cannot certify child bytes or act as
a final release plan. `demo/cmake/ReleaseMaterial.cmake` creates independent main and decoy
roots. Incremental child-source changes retain that root; changing generation inputs,
removing its outputs or explicitly regenerating them chooses another. Each package still
uses a fresh content key and nonce.

`prepare_release.py --material <early.json>` checks the existing header and binds the exact
final child and report. It writes only the late plan, preserving upstream header bytes and
mtime. Its original four-positional child-first mode remains available. No final child hash
feeds the root, executable correction generation or an earlier compiler input. The existing
64-byte release record and data-only parent finalizer remain unchanged. Future code-hash
providers must instrument code before final measurement and obey this acyclic ordering.

## Compiler and packaging boundary

`tools/payload_binding.py` builds the private `owned-context-v1` reference from the early
eight-word fold and actual routing ID. Its recipe overlay requires100 percent original-edge
coverage for the private owner. Existing exact overrides for `pyobf_demo_compute` are inherited
unless the helper has its own override; disabling or conflicting with required contribution
selection is refused. The demo's default deep selection follows the math into the private
helper, retaining integer and decoy protection.

`PayloadBinding.cmake` enables the consumer only in actual payload IR. Source-session fixtures
keep their reference body and existing declared coverage. Strict default markers cover three
application and49 SDK/context/client definitions; decoupled covers two and47. Assets or archive
runtime add their own reported definitions. Counts are inventories, not proof of binding.

The compiler records SHA-256 of the private bytes actually read. Before publishing outputs,
`pack_payload.py --contribution-input <reference.json>` checks that digest, the early fold,
the selected final owner, actual query/IR proof and complete original-edge coverage. A child
advertising the bound owner cannot silently omit this input. Wrong references, absent proof
and incompatible recipes fail. These checks establish consistency inside a trusted build;
they do not authenticate attacker-fabricated reports or a replaced compiler.

For the strict, non-POST, archive-off schema1 child, the final-image checker also checks
that each owned source query's returned value reaches its CFF state update. The production
test compiles and links a child whose site-701 query remains present but whose returned SSA
value is detached. The original child completes with the actual private source; the mutant
is refused by the final checker and cannot complete the protected result after admission
and query. This is a scoped return-flow check, not a general machine-level per-site proof.
Schema2 grouped owned queries still need separate multi-return analysis;
`individual_sites_verified` remains false.

The strict legacy `int pyobf_demo_compute(int)` export returns `-103`. It has no unbound copy
of the math. The private helper has a stable internal compiler label and is not exported.
The supported entry receives the expected lease through the existing versioned handoff,
scoped publication and lifecycle checks. It introduces no implicit successful-context cache,
public context ABI change or public lease-capture operation.

## Opt-in post-release code observations

`PYOBF_NATIVE_DEMO_POST_CODE_HASH=ON` selects a second strict Windows profile. It requires
SDK markers and the implemented measured-scope backend; it is independent of
`PYOBF_NATIVE_DEMO_PRE_CODE_HASH`. The latter still protects startup key reconstruction.
Both options default to OFF. The private same-build handoff is now version3 in all demo
profiles; the public owned-context ABI remains version1.

The build creates one random32-byte program root before child compilation, separately from
the path-fold material. Its private source reference selects two function identities:

| Consumer | Actual observed subject | Lifetime |
| --- | --- | --- |
| `pyobf_demo_protection_wrapper` | Final loaded parent's `.text`, or an explicitly selected complete function contribution | Its invocation-owned snapshot and parent lease survive the nested computation |
| `pyobf_demo_bound_compute` | Final loaded child's `.text`, or an explicitly selected complete function contribution | A different owner, read, snapshot, envelope and operation scope |

Each consumer uses `measured-scope-v1` with100 percent original normal-edge binding.
`PYOBF_NATIVE_DEMO_POST_SUBJECTS` optionally selects exact parent/child functions using the
[frozen subject contract](NATIVE_FUNCTION_SUBJECTS.md#early-post-role-host-selection).
Selection precedes codegen; actual non-LTO objects and exact final ranges are required at
completion. Both outer CFF and the explicit outer-CFF-OFF object path use this same boundary.
The default empty setting keeps both `.text` subjects. This is a selected-function boundary,
not automatic protection of its ordinary or generated helper callees.
The helper constructing both scopes explicitly uses hybrid EH so normal and exceptional
returns release their resources. Stage7 marks arrival at the wrapper's user callback;
the successful real trace becomes1,2,3,4,5,7,6. Decoy traces keep their separate meaning.

For outer-CFF-ON POST builds, separate compiler gates verify each fixed parent
creator result reaches its owner, lease and handoff slot and that both successful
role results gate ready publication. The child gate traces each role's observation
and checked Snapshot into the matching Scope, wrapper/compute forwarding and
measured CFF marker sites 702/701. It rejects a path that reaches the consumer
after either Snapshot check fails. The production final checker joins both
compiler reports with the exact owner plan/slot layout, emitted parent creator
code, child private site catalog, release report and parent/child images. Swapped
roles, shifted slot offsets, remapped sites and stale artifacts fail. Its report
scope is compiler flow plus function-level final machine presence; individual
site machine presence and generated-owner independence remain unverified.

The parent admits only a bounded56-byte private version2 role/domain/source/generation
frame after payload entry and post preparation. The frame carries the observation
instance and actual context identity from the snapshot's retained lease. Preparation
registers each role's exact owner in the parent; retirement removes both registrations.
The response supplies the live generation, never the expected contribution word. The
post profile rejects the legacy48-byte word service. The child derives each word from
the actual full digest, authenticated material and fixed source framing; a successful
lifecycle response does not replace these inputs. A copied digest and a synthetic
same-generation context cannot substitute for a revoked registered observer.
Startup key admission, its readiness recheck and post preparation compare the expected
lease's actual context with the live session owner. Numeric generations are factory-local
and can collide between DLLs; matching numbers cannot replace origin identity. A separate
source-built SDK fixture exercises that collision without corrupting either context state.
This source binding is local in-process producer/consumer provenance; it does not
authenticate against a process-memory attacker able to replace both parent and child code.

The parent plan also binds the exact early private reference bytes, preventing a root
rotation from retaining the same plan identity merely because parent code is unchanged.
Only after both images are linked does the composer fill the reserved reference/material
slots and release mask. The child receives runtime views rather than compiling a final
parent digest into its code. No final hash feeds code generation. `finalize_post_release.py`
validates the exact child, child report, early sources and release plan, then uses the same
data-only write proof as existing finalizers. Existing nonzero storage is authenticated,
not silently resealed against a new subject.

The first integrated policy is per-use with explicit1s scan/use budgets. Two live owners
and their snapshot/cache storage are distinct; generated per-owner observer code and
compiler/linker anti-merge proof remain required. The immutable program root is shared
between function-domain derivations, not a distinct random root per owner. Generated-helper
coverage, additional policy/source combinations and metadata freshness reporting
remain open. Measurements are interval observations, not continuous integrity checks;
code can change after a successful observation. DLL initialization already ran before
post observation. The disk-backed replacement window and runtime dumping remain outside
this profile's protection claim.
The actual probe damages each role separately. Wrapper failures stop before stage7;
compute-role failures occur after the valid wrapper callback and before computation can
complete. These cases require the backend's exact `0x702` protection-failure reason,
so an unrelated crash or a probe assertion cannot satisfy the negative.
The same probe verifies exact registration/retirement and rejects an independent SDK
context that replays copied valid evidence after the real observer has been revoked.

## Checks and measurements

`pyobf_native_demo_payload_binding` loads the actual DLL. Detached exports/empty handoff refuse;
a host admitted by the old lifecycle Boolean supplies wrong or unavailable contribution
words and cannot complete the protected algorithm. The checker also exercises private-root,
report, recipe and non-overwriting package failures. In decoupled mode it demonstrates that
the admitted fake host completes without a source query. Normal completion and teardown use
the existing real outer smoke, lifetime and release tests; these cover exceptions, reentry
and concurrent calls. `check_release_plan.py` includes early/late schema and non-rewrite tests.
The standalone decoy build checks its independent dependency chain.

The existing `pyobf_native_demo_measure_cff` target chooses `measure_payload.cpp` in strict
mode. It compares actual inner-entry execution with the original combined source before
ordinary optimization, CFF and archive transformation, using a real CNG-derived source and
owned host context. To isolate a source-O2 profile from its ordinary optimization benefit,
invoke the same driver with the actual pre-archive `payload.optimized.ll` as its reference
IR input. The output records that exact IR and both images; neither pair isolates individual
query instructions. Startup
includes inner load, context, one entry and cleanup; hot samples retain the DLL/context and
include handoff, publication/reset, lifecycle and source requests. It records exact input,
image, reference and harness hashes. This measures the whole transformation profile, not
isolated query instructions. The separate existing bootstrap measurement includes outer
authentication, file release, loading and cleanup with the actual strict child.
For the post profile, use `pyobf_native_demo_measure_bootstrap`: the isolated payload-only
harness still implements the legacy owned-word protocol and is unsupported for
`measured-scope-v1`. The bootstrap driver records exact post inputs and the full-release
scope; its result must not be presented as isolated CFF or body-only overhead.

## Limits and remaining work

The fold is local white-box software material. This raises static recovery cost and binds
the admitted path; it is not TPM protection, issuer/device authorization, independent measured
readiness or runtime secrecy against dumping and patching. A missing raw eight-word table
is one bounded check, not a secrecy proof. Wrong CFF paths may crash or fail to terminate.
The disk-backed loader replacement window remains a separate boundary.

Other required provider adapters, independent code observations/caches and freshness,
hash-cycle avoidance, the remaining D5 startup readiness and final D8 matrix/cost acceptance
remain open. See [contribution gates](NATIVE_CONTRIBUTION_GATES.md),
[release records](NATIVE_RELEASE_RECORDS.md), [handoff](NATIVE_DEMO_HANDOFF.md) and
[bootstrap acceptance](NATIVE_BOOTSTRAP_ACCEPTANCE.md).
